# 设计稿2：权限矩阵 + 资源归属规则（逐 API role/scope/org 校验）

版本：M0-FREEZE / 2025-12-24  
依据：Sheet「权限矩阵(已对齐)」「决策一页：接口级权限与资源归属校验」

## 1. 目标

- 所有 API 必须可回答 3 个问题：
  1) 谁（role/scope）可以调用？
  2) 调用者可以访问哪一行数据（org_id + ownership）？
  3) 越权时返回什么（403/404 策略）？

## 2. 权限模型（执行口径）

### 2.1 统一鉴权入口
后端必须实现统一的 `authorize()` 中间件/函数：
- 校验 JWT / Session（外部 IdP）
- 解析 `role`、`org_id`、`userId`、（可选）`ownerId/tenantId`
- 将这些写入 request context，供后续查询与 RLS 使用

### 2.2 org_id 强制过滤
- 任何读取/写入业务表必须带 `org_id` 条件
- 若启用 RLS：每个请求先执行 `set_config('app.org_id', :org_id, true)`

### 2.3 资源归属校验（IDOR 防护）
资源归属校验必须在“读取资源”那一步完成，例如：
- Tenant 只能访问与自己 tenantId 绑定的 application/lease/ticket/invoice
- Owner 只能访问与自己 ownerId 绑定的 property/lease/invoice/ticket
- Admin/Staff 可访问 org 内所有资源（仍受 org_id 约束）

### 2.4 403/404 策略
- 推荐：**越权访问返回 404**（避免暴露资源存在性）
- 仅当确需提示“你没有权限”且资源可公开存在性时，返回 403

> 逐接口默认策略在权限矩阵表中（列：错误策略 403/404）。

## 3. 权限矩阵（冻结版）

权限矩阵定版文件：
- `03_TABLES/权限矩阵(已对齐).xlsx`
- 同步提供 csv：`03_TABLES/权限矩阵(已对齐).csv`

工程执行要求：
- 每条接口在实现时必须标注对应行（可在代码注释/route 定义上写 row id）
- 每次改动权限必须更新矩阵并触发评审

## 4. 防返工规则（强制）

- 禁止“前端隐藏按钮 = 权限控制”：所有权限必须由后端 enforce
- 禁止双写：CRM/Admin/Owner/Tenant 所有写路径统一打到 Core（同一套权限和规则）
